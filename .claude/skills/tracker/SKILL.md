## Сценарий

1. Прочитай `KNOWLEDGE.md` и соседний `../extract-price/SKILL.md`. Применяй именно сценарий `extract-price` к каждому URL из таблицы: один входной URL → один объект `{ regular_price, sale_price, has_credit }`. Если нет отдельной команды вызова скилла, исполни его инструкции как агент для каждой страницы. Не дублируй алгоритм извлечения в tracker.
2. Открой все пять страниц заново доступным инструментом, не используй результаты прежних прогонов или проверок как новые данные. Независимые чтения допустимо выполнять пакетно. Для каждой страницы проверь товар/SKU и условия из таблицы через extract-price.
3. Сохрани результат каждого извлечения в памяти: `id`, `name`, `url` и три поля объекта цены. Обрабатывай разные предложения одного SKU отдельными строками. Ошибка одной страницы не останавливает остальные: включи и её строку с результатом по правилам extract-price и отдельным объяснением ошибки.
4. Проверь полноту: ровно пять строк, уникальные id, каждый URL из списка представлен один раз. Если инструмент недоступен, отметь непроверенные строки; не объявляй обход успешным. Не придумывай цены. Проверь типы объекта по контракту extract-price; некорректный ответ перепроверь, при неудаче отметь ошибку вместо выдуманных данных.
5. Верни одну цельную Markdown-таблицу: `Товар | URL | regular_price | sale_price | has_credit`. Покажи числа без символа валюты, отсутствие цены как `null`, boolean как `true`/`false`. Укажи RUB перед таблицей. Весь список должен появиться в одном итоговом ответе.
6. Отдельно от таблицы укажи дату/время чтения с часовым поясом, число обработанных URL и диагностику по id: доступность страницы, кеш/неизвестную свежесть, ограничения оплаты/наличия и ошибки. `false` означает отсутствие подтверждённого кредита, а не гарантированное отсутствие такой услуги. Ссылки в таблице ведут на страницы-источники. Кеш не называй текущей ценой магазина.

## Границы этого шага

Сейчас результат — таблица одного прогона. Не записывай историю в tracker-data, не рассчитывай diff и не отправляй Telegram: эти этапы добавляются следующими шагами. По отдельной просьбе можно сохранить демонстрацию проверки в docs, явно пометив её как пример, а не рабочую историю.
