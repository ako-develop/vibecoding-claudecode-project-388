# Правила трекера

## Постановка

Ниша: SO-DIMM DDR5-5600 комплектом 2×16 ГБ и Samsung 980 PRO на 1–2 ТБ.
Цель: заметить снижение цены для покупки памяти и SSD. Локация — Россия, валюта — RUB.
Регион сравнения по умолчанию — Москва, если карточка явно не относится к другому региону; регион фиксируется для каждой ссылки.
Стартовый список — `products.json`, журнал проверки — `docs/url-check.md`.
Сравнивать каждую карточку с её собственной историей. Не смешивать цены разных магазинов, регионов и способов оплаты.
Совместимость накопителя с устройством пользователя пока не подтверждена.

## Контракт цены

Определение для выбранных карточек; инструкция `extract-price` находится в `.agents/skills/extract-price/SKILL.md`.

- `regular_price`: полная обычная цена товара, включая явно показанную зачёркнутую цену до скидки. Если показана только одна обычная цена, она записывается сюда.
- `sale_price`: полная публичная цена со скидкой. Если скидка не указана — `null`. Не подменять её ежемесячным платежом или персональной ценой по карте.
- `has_credit`: `true`, если для товара явно предлагается кредит или рассрочка; иначе `false` (подтверждённого предложения не найдено). По контракту это всегда boolean. При ошибке чтения обе цены — `null`, `has_credit` — `false`; это не доказательство отсутствия кредита. Причину ошибки вызывающий процесс фиксирует отдельно.

Цены записываются числами в одной выбранной валюте. Недоступная цена — `null`, никогда не ноль. Ошибка загрузки не означает снижение цены.

Регион и валюта должны оставаться одинаковыми между прогонами. Доставку и персональные скидки не смешивать с публичной ценой товара.

Для Онеком отслеживать полную цену при наличном расчёте; безналичная цена — другой способ оплаты, не скидка. Для Борн — опубликованную безналичную цену с НДС. Для Softline — публичную цену для юридических лиц и ИП, только как рыночный ориентир: это не предложение для личной покупки. Клубную цену KNS не учитывать.

Если указана только «последняя цена» отсутствующего товара, текущие `regular_price` и `sale_price` равны `null`. Отсутствие товара, предзаказ, запрет доступа и ошибка загрузки — разные состояния, их нужно отмечать в результате обхода. Не превращать их в уведомления о скидке.

## Значимость изменений

Сопоставлять строки по точному URL. Значимым считать изменение обычной или скидочной цены по модулю не менее 1% от прежнего значения: (новая − старая) / старая × 100. Сравнивать Decimal без округления перед проверкой порога; копеечные колебания ниже 1% отбрасывать.

Появление/исчезновение скидочной цены и изменение has_credit — значимы независимо от процента. Новый URL и исчезнувший из списка URL — значимые изменения состава; первый прогон только создаёт базу, список всех товаров как новости не выдавать.

null — неизвестная цена, не ноль. Переход обычной цены в null или обратно — диагностика доступности данных, не скидка. Если хотя бы одна строка пары недоступна/некорректна, её цены и has_credit не сравнивать: false при ошибке не означает отмену рассрочки. Для появления/исчезновения скидки нужны известные обычные цены с обеих сторон; иначе диагностика. Исчезновение URL из списка отличается от ошибки чтения карточки, которая остаётся строкой снимка.

Валюту, регион, SKU и основу оплаты проверять до сравнения: изменение условий — диагностика, а не движение цены. Для старых строк без статуса чтения свежесть неизвестна. Кеш можно сравнивать с явной оговоркой: это изменения наблюдений, не подтверждённые текущие цены. Сбой чтения истории или повреждённый JSON не считать первым запуском; остановить сравнение и не перезаписывать историю.

Машиночитаемый порог для scripts/diff.py (единственный источник порога):

<!-- diff-policy -->
```json
{"price_change_percent": 1}
```

## Хранение прогонов

Приватный репозиторий `ako-develop/tracker-data`, ветка main. Через GitHub MCP создаётся UTF-8 JSON в корне, имя YYYY-MM-DD.json по дате начала прогона в Europe/Moscow. Формат schema_version=1: run_date, collected_at (ISO 8601 со смещением), timezone, currency, items. Полная схема строки описана в скилле tracker.

Один дневной снимок на дату; повторные прогоны того же дня обновляют файл отдельными коммитами, сохраняя предыдущие версии в Git. Другие даты не перезаписывать. Признак кеша и ошибки чтения хранятся рядом с ценами: дата обращения не доказывает свежесть цены магазина.

## Доставка в Telegram

После успешного сохранения и проверки снимка отправлять одну короткую сводку через send.py. Одна строка на значимый товар: название, изменения «было → стало», процент/скидка/рассрочка и URL. Только significant_changes; raw_diff в сообщение не включать. Неизвестную цену не называть нулём. Для кеша явно писать «Данные из кеша; актуальность цен не подтверждена».

Если значимых изменений нет — отправлять «Значимых изменений цен нет». Первый прогон — «Создана база для сравнения: N товаров», без выдуманных изменений. Ошибки чтения/смена условий добавляются короткой диагностикой: отсутствие значимых изменений не означает успешную проверку всех цен. Если сохранение не удалось, сводку не отправлять, сообщить пользователю об ошибке сохранения.

Токен и получатель задаются TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID в окружении либо локальном .env рядом с send.py. Переменные окружения имеют приоритет. .env исключён из Git; .env.example содержит только пустые поля. Использовать получателя из настроек проекта, не подменять его старым каналом из других заданий.

Сводка — обычный текст, без parse_mode. Длинные сообщения разбивать по строкам на части до 4096 символов. Перед сетевой отправкой сохранить подготовленный текст во временный файл. При успехе send.py печатает «Отправлено.». При ошибке доставки не собирать новый прогон ради повтора: использовать сохранённую сводку. При сетевом таймауте доставка может уже состояться — сначала проверить чат; автоматически повторять нельзя.
