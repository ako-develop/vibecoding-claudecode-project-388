# Проверка агента сводки — 05.11.2026

Вместо Haiku используется Codex sub-agent на gpt-6-luna, reasoning low.
Конфигурация: `.codex/agents/telegram_summary.toml`. tracker передаёт готовые
изменения и правила, проверяет ответ и сам вызывает send.py. Агент оформления
не получает секретов и не выполняет операции с историей или Telegram.

Конфигурация соответствует [официальному формату пользовательских агентов](https://learn.chatgpt.com/docs/agent-configuration/subagents).
TOML проверен через tomllib; копии tracker в .agents и .claude совпадают.
В текущем сеансе проверен прямой spawn с явными моделью и effort, без наследования
истории; инструкции переданы в задаче. Автоматическое обнаружение нового TOML
в новом сеансе отдельно не проверялось.

## Сравнение на одинаковых данных

Для проверки использованы только синтетические изменения: SSD 20 000 → 18 000 ₽
(−10%, порог 1%) и has_credit=true → false у памяти. URL — example.com.
Эти данные не записывались в tracker-data и не отправлялись как реальные предложения.

Вариант основной модели:

```text
Трекер цен · 05.11.2026, 22:41 МСК
Учебный пример: изменения синтетические
Тестовый SSD — 20 000 → 18 000 ₽ (−10%); порог 1%; https://example.com/ssd
Тестовая память — рассрочка больше не подтверждена; изменение рассрочки; https://example.com/ram
Данные из кеша; актуальность цен не подтверждена
```

Первый ответ Luna сохранил оба товара, URL, учебную пометку и ограничение кеша,
но пропустил ₽ и переданный процент. Основной агент обнаружил это и отправил
одно уточнение. Исправленный ответ:

```text
Трекер цен · 05.11.2026, 22:41 МСК

Тестовый SSD — 20 000 → 18 000 ₽ (−10%); причина: порог 1%; https://example.com/ssd

Тестовая память — рассрочка больше не подтверждена; https://example.com/ram

Учебный пример: изменения синтетические
Данные из кеша; актуальность цен не подтверждена
```

После уточнения факты, проценты, валюта, URL и ограничения сохранены. Есть
стилистическое отличие — пустые строки. На этом малом примере результат пригоден
после проверки; равное качество с первой попытки не подтверждено. Проверка всех
URL/значений/процентов и одно уточнение включены в tracker, затем предусмотрено
оформление основной моделью, если ошибка остаётся.

## Доставка настоящего результата

Тот же отдельный агент оформил пустой diff сохранённого снимка 22:41:01+03:00:
5 из 5 товаров, кешированные источники, значимых изменений нет. Новый обход
магазинов для проверки оформления не выполнялся. Использован снимок, запись и
обратное чтение которого подтверждены в [проверке Telegram](telegram-check.md).

```text
Трекер цен · 05.11.2026, 22:41 МСК

Значимых изменений цен нет

Обработано: 5 из 5
Данные из кеша; актуальность цен не подтверждена

Проверка агента сводки по сохранённому снимку
```

После проверки текст передан `python3 send.py --file /tmp/tracker-summary-agent-message.txt`.
Код выхода 0, «Отправлено.»: Telegram API подтвердил доставку сообщения. Просмотр
пользователем не проверялся. Существующие 13 тестов diff/send.py прошли.

Уточнение: эта первоначальная сводка ушла через ошибочно настроенного бота.
Настройки затем исправлены; успешный тест отдельного @ako_vibecoding_test_bot
зафиксирован в разделе «Уточнение получателя» [отчёта доставки](telegram-check.md).

## Стоимость и вывод

Для оценки используются опубликованные стандартные API-тарифы короткого контекста:
[gpt-6-luna](https://developers.openai.com/api/docs/models/gpt-6-luna) — $0.10 за
миллион входных и $0.50 за миллион выходных токенов;
[gpt-6.1-sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) — $2 и $10
соответственно. При одинаковом количестве некешированных токенов оформление
на Luna расчётно дешевле в 20 раз. Например, 1000 входных + 200 выходных токенов:
$0.0002 против $0.004. Это пример расчёта, не измеренный расход этого сеанса и
не обещание снижения стоимости всего tracker в 20 раз.

Точные токены и списания отдельных запусков интерфейс проверки не предоставил.
Повторное уточнение, инструкции агента и проверка основной моделью тоже требуют
ресурсов. При пяти товарах абсолютная экономия мала, а первый ответ потребовал
исправления; практическая экономия на этом объёме не доказана. Делегирование
оставлено как учебный вариант. При росте объёма полезно измерить расход и долю
ответов, которые проходят проверку с первого раза.
