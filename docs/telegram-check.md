# Проверка доставки Telegram

Подготовлен send.py на стандартной библиотеке urllib. Поддерживает текст аргументом и UTF-8 файл через --file. Настройки читаются из окружения или .env рядом со скриптом; окружение имеет приоритет. Успешный ответ ok=true с message_id печатает «Отправлено.»; ошибки не выводят токен, URL запроса и тело ответа. Автоматических повторов нет.

Команда `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v` выполнила 13 тестов: 8 для diff и 5 для отправки. Проверены JSON POST с Unicode и обычным текстом, приоритет окружения, ответ успеха, ошибки Telegram/сети без раскрытия токена, отсутствие повторов, пустые и слишком длинные сообщения. Сеть в тестах заменена mock; они не подтверждают доставку в настоящий чат.

Локальный .env создан с пустыми TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID, права 600. git check-ignore подтвердил исключение .env; в .env.example только пустые ключи. Значения настроек не выводились.

Запуск `python3 send.py "тест"` пока завершился кодом 1 с просьбой заполнить настройки. Сетевого запроса не было: токен и chat id отсутствуют. Реальная проверка сообщения «тест» и сводки tracker остаётся до заполнения локального .env пользователем и первого сообщения боту.

Принято поведение: при пустом significant_changes отправлять «Значимых изменений цен нет». При кеше указывать ограничение свежести. При неудачной записи истории сводку не отправлять, при ошибке доставки хранить готовый текст для повторной отправки без нового прогона.
