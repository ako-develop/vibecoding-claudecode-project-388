# Проверка доставки Telegram

Подготовлен send.py на стандартной библиотеке urllib. Поддерживает текст аргументом и UTF-8 файл через --file. Настройки читаются из окружения или .env рядом со скриптом; окружение имеет приоритет. Успешный ответ ok=true с message_id печатает «Отправлено.»; ошибки не выводят токен, URL запроса и тело ответа. Автоматических повторов нет.

Команда `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v` выполнила 13 тестов: 8 для diff и 5 для отправки. Проверены JSON POST с Unicode и обычным текстом, приоритет окружения, ответ успеха, ошибки Telegram/сети без раскрытия токена, отсутствие повторов, пустые и слишком длинные сообщения. Сеть в тестах заменена mock; они не подтверждают доставку в настоящий чат.

Локальный .env создан с правами 600 и затем заполнен пользователем. git check-ignore подтвердил исключение .env; в .env.example только пустые ключи. Значения настроек не выводились.

## Реальная проверка 05.11.2026

После заполнения .env выполнен `python3 send.py "тест"`. Первое обращение из ограниченного окружения завершилось ошибкой; отдельная DNS-проверка подтвердила, что api.telegram.org не разрешался, поэтому HTTP-запрос не дошёл до Telegram. Затем с разрешённым сетевым доступом команда завершилась кодом 0 и вывела «Отправлено.». send.py проверил ответ Telegram ok=true с message_id; токен и ID получателя не записывались в отчёт.

Выполнен полный прогон tracker: через GitHub MCP прочитан предыдущий снимок, заново открыты все пять карточек, выполнен diff. Значимых изменений нет. Данные источников остаются кешированными. Новый снимок 22:41:01+03:00 сохранён через MCP и прочитан обратно; содержимое совпало.

Коммит истории: https://github.com/ako-develop/tracker-data/commit/6f6375fc952bd6a944402f46c3101693bc654678

После проверки сохранения подготовлена и отправлена через `python3 send.py --file /tmp/tracker-message.txt` сводка:

```text
Трекер цен · 05.11.2026, 22:41 МСК
Значимых изменений цен нет.
Обработано 5 из 5 товаров: Samsung 980 PRO и SO-DIMM DDR5.
Данные из кеша; актуальность цен не подтверждена.
```

Команда завершилась кодом 0, «Отправлено.»: Telegram API подтвердил отправку. Просмотр сообщения пользователем не проверялся. Доставка непустой сводки с реальными изменениями пока не проверена: наблюдаемые цены не изменились, искусственные изменения в рабочую историю не вносились.

Принято поведение: при пустом significant_changes отправлять «Значимых изменений цен нет». При кеше указывать ограничение свежести. При неудачной записи истории сводку не отправлять, при ошибке доставки хранить готовый текст для повторной отправки без нового прогона.
